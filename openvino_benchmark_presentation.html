Benchmarking OpenVINO models

A performance study across CPU, GPU and NPU, three precisions (INT4 / INT8 / FP16) and two serving modes — built to answer one question: which configuration actually benefits from the GPU?

Qwen2.5-7B · Stable Diffusion
How it started

The first workload did not benefit from the GPU.

While discovering OpenVINO, the initial test was a quantized LLM serving one request at a time. Across INT4, INT8 and FP16, the GPU stayed at or below CPU throughput — between 0.90× and 0.96×.

Project direction

Search for the configuration where the GPU pays off.

Instead of stopping at “GPU is not faster”, the benchmark harness was reused to vary the workload, the precision and the batch size — and to measure the point where GPU acceleration becomes worthwhile.

Generation throughput

log scale

At batch 1, the GPU is not an accelerator — it is a parity device.

  • CPU wins every quantized precision. INT4 is the fastest single-request configuration: 16.8 tok/s, 59.6 ms TPOT and 0.87 s TTFT.
  • GPU lands at 0.90–0.96× CPU across INT4, INT8 and FP16 — slightly slower, never faster.
  • GPU startup is 6.6–24.7× more expensive than CPU: 6.5–14.6 s vs 0.6–1.0 s load + compile.
  • NPU is not competitive: 7.0 tok/s, 130 ms TPOT, 49 s TTFT and 39 s startup on INT4.

Generation throughput

log scale

Batching is the lever. FP16 is where the GPU takes over.

  • Throughput scales hard on CPU: INT4 goes 16.8 → 65.6 tok/s (3.9×); GPU INT4 goes 15.3 → 41.6 tok/s (2.7×).
  • The cost is latency: CPU INT4 TTFT jumps 0.87 → 10.7 s; GPU INT4 0.99 → 14.6 s. Batching trades responsiveness for throughput.
  • GPU's first real win — FP16 batched: 23.5 vs 13.2 tok/s and 42 vs 75 ms TPOT (1.78× over CPU).
  • But quantized CPU still wins on absolute throughput: 65.6 tok/s INT4 beats every GPU configuration.

Time per generated image

lower is better
log scale

The GPU wins every image-generation configuration — by 1.2× to 2.0×.

  • FP16 is the GPU's sweet spot: 26.2 s per image single, 24.4 s batched — the best result in the study.
  • Batching helps the GPU, hurts the CPU: GPU INT8 31.4 → 29.3 s and FP16 26.2 → 24.4 s; CPU INT8 37.2 → 42.0 s and FP16 47.0 → 48.6 s.
  • INT8 narrows the gap: the smallest GPU advantage is 1.19× (INT8, single request).
  • Consistent direction: unlike LLM inference, image generation rewards the GPU in all eight measured cases.
